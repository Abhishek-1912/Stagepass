# Deploying Stagepass to Render

This is the step-by-step guide for putting Stagepass online. Every step that needs an account, a password or a
secret is yours to do; nothing here should be pasted into chat or committed to git. Allow about an hour the first
time.

You will end up with two Render services in Singapore:

| Service | What it is | Example address |
|---|---|---|
| `stagepass-api` | The Spring Boot API (Docker) | `https://stagepass-api.onrender.com` |
| `stagepass-web` | The React site (static) | `https://stagepass-web.onrender.com` |

Render shows the real addresses after the first deploy. Wherever this guide says `<api>` or `<web>`, use those.

---

## 1. Before you start

Have these ready (all from accounts you already use for local development):

- **Supabase** project (the same one, or a new Mumbai project for launch — see Plan 11).
- **Cloudinary** cloud name, API key and API secret.
- **Resend** API key (and, for launch, a verified sending domain).
- **Razorpay** test-mode key id and key secret.
- A **GitHub** account with access to `Abhishek-1912/Stagepass`.

Two values you create yourself, once, and keep in your password manager:

- `PAYOUT_ENCRYPTION_KEY` — 32 random bytes, base64. Generate one with:

  ```bash
  openssl rand -base64 32
  ```

  Use the **same** value forever for a given database: it decrypts organizers' saved bank account numbers.
  (`QR_SECRET` is generated by Render for you. Never change it after launch: it would invalidate every issued ticket.)
- `RAZORPAY_WEBHOOK_SECRET` — any long random string; you will paste the same value into Razorpay in step 5.

## 2. Supabase settings

1. **Database URL (pooler, session mode).** Supabase → Project → **Connect** → *Session pooler*. You need three
   values from it:
   - `DB_URL`: `jdbc:postgresql://<host>.pooler.supabase.com:5432/postgres?sslmode=require`
     (take the host from the connection string; keep port **5432** = session mode).
   - `DB_USERNAME`: `postgres.<project-ref>` (as shown there).
   - `DB_PASSWORD`: your database password.
2. **Project URL.** Project Settings → API → *Project URL* → this is `SUPABASE_URL` (and `VITE_SUPABASE_URL`).
   The *anon public* key is `VITE_SUPABASE_ANON_KEY`.
3. **Auth URLs** — do this after step 4, when you know `<web>`: Authentication → URL Configuration:
   - *Site URL*: `<web>`
   - *Redirect URLs*: add `<web>/**`
   Keep `http://localhost:5173/**` too if you still develop locally against this project.

## 3. Create the Render services

1. Sign up at render.com with your GitHub account and allow it to read the `Stagepass` repository.
2. Render dashboard → **New → Blueprint** → pick the repository → branch `main`. Render reads `render.yaml` and shows
   both services.
3. Render asks for every value marked `sync: false`. Fill them in:

**stagepass-api**

| Variable | Value |
|---|---|
| `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | from step 2.1 |
| `SUPABASE_URL` | from step 2.2 |
| `WEB_BASE_URL` | `<web>` — first time, use the address Render shows for `stagepass-web` |
| `CORS_ALLOWED_ORIGINS` | `<web>` (same as above, no trailing slash) |
| `BOOTSTRAP_ADMIN_EMAILS` | the email address that should be the first admin |
| `PAYOUT_ENCRYPTION_KEY` | the value you generated in step 1 |
| `RESEND_API_KEY`, `RESEND_FROM` | Resend key; sender such as `Stagepass <onboarding@resend.dev>` until your domain is verified |
| `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` | Cloudinary dashboard |
| `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET` | Razorpay test-mode keys |
| `RAZORPAY_WEBHOOK_SECRET` | the string you created in step 1 |
| `COMPANY_GSTIN`, `COMPANY_STATE`, `COMPANY_NAME`, `COMPANY_ADDRESS` | your company's details (for invoices) |

`QR_SECRET` is generated automatically. `SPRING_PROFILES_ACTIVE` is already `prod`.

**stagepass-web**

| Variable | Value |
|---|---|
| `VITE_API_BASE_URL` | `<api>` (no trailing slash) |
| `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` | from step 2.2 |
| `VITE_GOOGLE_MAPS_KEY` | leave empty for now (maps fall back to an "Open in Google Maps" link) |

4. Click **Apply**. The API takes 5–10 minutes to build the first time; the web site about 2 minutes.
   - If the API stops with `Missing required environment variables: …`, add the named variables in
     *stagepass-api → Environment* and redeploy.
   - The API runs the database migrations itself on start.
5. If the addresses Render gave differ from what you typed in `WEB_BASE_URL` / `CORS_ALLOWED_ORIGINS` /
   `VITE_API_BASE_URL`, correct them in each service's **Environment** tab and **Manual Deploy → Deploy latest
   commit** (the web site must be rebuilt for a `VITE_` change).
6. Now do step 2.3 (Supabase Auth URLs).

The API uses the **Starter** plan on purpose: free instances sleep, which delays Razorpay webhooks and first loads.

## 4. Check the API is up

Open `<api>/actuator/health` — it should show `{"status":"UP"...}`.

## 5. Razorpay webhook

Razorpay Dashboard (Test Mode) → Account & Settings → **Webhooks** → **Add new webhook**:

- URL: `<api>/api/v1/webhooks/razorpay`
- Secret: your `RAZORPAY_WEBHOOK_SECRET`
- Active events: `payment.captured`, `payment.failed`, `order.paid`, `refund.processed`, `refund.failed`,
  `payment.dispute.created`, `payment.dispute.won`, `payment.dispute.lost`, `payment.dispute.closed`

## 6. Resend

Until your domain is verified, Resend only delivers to the email address of the Resend account owner. Booking emails
to anyone else are kept in the outbox and marked failed — that is expected in test mode. Verifying a domain is part
of Plan 11.

## 7. First deploy smoke checklist

Do these in order on `<web>`; each should work without errors.

1. `<api>/actuator/health` shows `UP`.
2. The home page loads, with the Stagepass header and no error banner.
3. Sign in with **Email code** using the `BOOTSTRAP_ADMIN_EMAILS` address. The account menu shows **Admin**.
4. In a second browser (or private window), sign in with another email and apply to become an organizer.
5. As admin: **Organizers → Applications → Approve**.
6. As the organizer: create a small event with a **free** ticket type, submit it.
7. As admin: **Event review → Approve**.
8. As a third account (or the admin): open the event, book one free ticket, open **My tickets → the ticket** — the QR
   code shows.
9. As the organizer: **Scanner** (`<web>/scan`) → pick the event → scan the QR from another phone (or type the ticket
   code). It shows **Welcome in**; scanning again shows **Already used**.
10. Optional, with Razorpay test keys: book a paid ticket and pay with UPI `success@razorpay`. The booking confirms;
    Razorpay → Webhooks shows the delivery as successful.

11. Rate limits key on the visitor's real IP. Render's proxy adds it to `X-Forwarded-For`, and the API reads it
    from the right of that header (Tomcat `RemoteIpValve`), so a visitor can't fake it. If many unrelated visitors
    ever report "Too many requests" together, ask your developer to check the client address the API sees in the logs.

If any step fails, note the step number and what you saw, and share the API logs from Render (*stagepass-api →
Logs*) with your developer. The logs are JSON lines; they never contain passwords or keys.

## 8. Updating

Every push to `main` deploys both services automatically (`autoDeploy: true`). Database migrations run on API
start. If a deploy fails, Render keeps the previous version running.
